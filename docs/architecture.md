# MoeQuick Gate 架构设计文档

## 1. 架构概述

MoeQuick Gate 第一版采用 MVVM 架构。

目标：

* 保持 UI 与业务逻辑分离
* 降低后续功能扩展成本
* 保持代码结构清晰
* 方便 Codex 按模块实现

整体架构：

View（FXML）

↓

Controller

↓

ViewModel

↓

Repository

↓

Data Source（SQLite）

---

# 2. UI 层设计

## 2.1 UI 技术

使用：

* JavaFX
* FXML
* Controller

界面采用 FXML 描述布局。

Controller 负责：

* 接收用户操作
* 绑定 UI 控件
* 调用 ViewModel

UI 层不负责：

* 数据存储
* 系统配置修改
* Shell 命令执行

---

## 2.2 界面结构

第一版固定界面结构。

主要界面：

MainScene

包含：

### 代理列表区域

负责展示：

* 用户创建的代理配置
* 当前选中的代理

### 组件状态区域

展示：

* APT 状态
* NPM 状态

每个组件拥有独立代理开关。

---

# 3. MVVM 设计

## 3.1 ViewModel 设计

采用多个 ViewModel。

避免所有逻辑集中到单个 MainViewModel。

---

## MainViewModel

职责：

* 管理主界面状态
* 协调不同 ViewModel
* 保存当前选择状态

---

## ProxyListViewModel

职责：

* 加载代理列表
* 添加代理
* 修改代理
* 删除代理
* 选择当前代理

数据来源：

Repository。

---

## ComponentStatusViewModel

职责：

* 管理组件状态
* 检测组件代理状态
* 控制组件开启/关闭代理

当前组件：

* APT
* NPM

---

# 4. 数据层设计

## 4.1 Repository

UI 和数据库之间增加 Repository 层。

职责：

* 隔离数据来源
* 管理数据读取和保存

当前实现：

SQLite。

未来可以替换：

* 其他数据库
* 文件存储
* 云端同步

上层无需修改。

---

## 4.2 数据存储原则

数据库只保存：

* 用户创建的数据
* 用户操作数据

数据库不保存：

* 系统当前代理状态

原因：

系统配置可能被：

* 用户手动修改
* 其他程序修改

因此真实状态必须实时检测。

---

# 5. 代理系统设计

## 5.1 MoeProxy

MoeProxy 表示用户创建的代理配置。

包含：

* 名称
* 地址
* 端口
* 协议类型

示例：

Clash 本机监听：

地址：

127.0.0.1

端口：

7890

---

## 5.2 当前代理逻辑

系统同时维护：

### 当前选择代理

表示用户当前选择的代理配置。

### 组件代理状态

每个组件独立管理。

例如：

当前代理：

Clash：

127.0.0.1:7890

组件：

APT：

开启代理

NPM：

关闭代理

---

## 5.3 代理切换逻辑

用户选择新的代理时：

流程：

View

↓

Controller

↓

ViewModel

↓

通知已开启组件

↓

IProxy 实现

↓

应用新代理

规则：

* 已开启代理的组件自动切换
* 未开启代理的组件保持关闭

---

# 6. IProxy 接口设计

IProxy 定义系统组件代理操作能力。

职责：

* 检测代理状态
* 开启代理
* 关闭代理

第一版接口能力：

* check()
* enable()
* disable()

具体实现：

APTProxyImpl

NPMProxyImpl

---

# 7. 系统交互设计

## 7.1 命令执行

所有系统命令统一通过 CommandUtil 执行。

例如：

APTProxyImpl：

负责：

* APT 代理逻辑

CommandUtil：

负责：

* 调用系统命令
* 获取执行结果
* 捕获错误

这样避免每个实现类重复处理命令执行。

---

## 7.2 权限处理

采用按需授权方式。

普通操作：

直接执行。

需要管理员权限时：

使用 pkexec 请求用户授权。

例如：

修改：

/etc/apt/

时：

弹出权限确认。

程序不在启动时要求 root 权限。

---

# 8. 组件实现

第一版支持：

* APT
* NPM

结构：

组件接口：

IProxy

实现：

APTProxyImpl

NPMProxyImpl

未来新增组件：

直接增加新的实现类。

第一版不设计：

* 插件系统
* 动态加载
* 插件生命周期管理

---

# 9. 状态检测

组件状态采用实时检测。

启动时：

自动检测：

* APT 当前代理状态
* NPM 当前代理状态

运行过程中：

监听相关配置变化。

配置变化：

更新界面状态。

---

# 10. 操作日志

日志采用纯文本文件保存。

用途：

* 记录用户操作
* 排查问题

记录内容：

* 时间
* 操作组件
* 操作类型
* 使用代理
* 执行结果

日志限制：

最大大小：

200KB

超过限制：

自动清理旧日志。

---

# 11. 第一版架构原则总结

MoeQuick Gate 第一版遵循：

1. 使用 MVVM 保持界面和逻辑分离。

2. 使用 Repository 隔离数据来源。

3. 使用 IProxy 抽象系统组件代理能力。

4. UI 不直接执行系统操作。

5. 系统命令统一通过 CommandUtil 执行。

6. 不提前设计插件系统。

7. 优先完成稳定可用的小工具。
