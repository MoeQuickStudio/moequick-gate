# MoeQuick Gate 产品需求文档

## 1. 项目概述

### 项目名称

中文名称：

萌快网络助手

英文名称：

MoeQuick Gate


### 项目定位

MoeQuick Gate 是一款降低网络环境配置复杂度的开发者助手。

项目目标：

帮助 Linux 开发者统一管理开发环境中的网络代理配置，减少不同工具之间代理配置分散导致的重复操作。


---

## 2. 背景与痛点

Linux 开发环境中，不同工具通常拥有独立的代理配置方式：

- APT
- NPM
- Git
- Pip
- Docker
- Curl
- Wget

这些工具可能分别使用：

- 环境变量
- 配置文件
- 用户级配置
- 系统级配置
- 服务配置

导致：

1. 不同工具代理配置分散
2. 代理切换需要重复修改多个位置
3. 用户难以快速了解当前网络环境状态


MoeQuick Gate 希望通过统一的管理界面降低配置成本。


---

### 第一阶段用户

本人。

运行环境：

- Ubuntu 24.04
- Linux 桌面开发环境


### 未来用户

降低网络环境配置复杂度。

用户关注：

> 我想使用哪个网络环境。

而不是：

> 我需要修改哪个配置文件。

# 5. MVP 范围

## 5.1 第一版目标

第一版实现：

- 管理多个代理配置
- 创建、编辑、删除代理配置
- 选择当前代理环境
- 独立控制组件代理状态
- 自动检测组件当前代理状态


第一版支持组件：

- APT
- NPM


---

## 5.2 代理模型

代理配置对象：

MoeProxy


包含字段：

- 名称
- 地址
- 端口
- 协议类型


支持代理类型：

- HTTP Proxy
- HTTPS Proxy
- SOCKS5 Proxy


主要适配：

Clash 等本地代理工具。


---

## 5.3 代理使用逻辑

系统存在两个独立状态：

### 当前选择代理

表示用户当前选择的代理配置。

例如：

```

Clash本机监听

127.0.0.1:7890

```


### 组件代理开关

每个组件独立管理：

例如：

```

APT:
开启代理

NPM:
关闭代理

```


当用户切换当前代理：

- 更新当前选择状态
- 已开启代理的组件自动切换到新代理
- 未开启代理的组件保持关闭状态

# 7. 数据设计原则

## 数据库存储原则

数据库只保存：

- 用户创建的数据
- 用户操作记录


不保存：

- 系统实际代理状态


原因：

系统配置可能被其他程序或用户手动修改。

真实状态必须通过实时检测获得。


---

## SQLite 数据

保存：

### 代理配置

proxy_profile

包含：

- id
- name
- host
- port
- protocol


### 当前选择代理

保存当前用户选择的代理配置。


### 操作历史

记录：

- 操作时间
- 操作组件
- 使用代理
- 执行结果

# 9. 开发原则

## UI 与实现分离

UI 层不直接处理系统配置。


调用关系：

```

Scene / Controller

```
    |

    |

 IProxy

    |

    |
```

APTProxyImpl
NPMProxyImpl

```


---

## 系统操作隔离

所有：

- 文件修改
- Shell 命令执行
- 系统配置操作

均由具体实现类负责。


UI 层不直接执行系统操作。

# 11. 第一版完成标准

Ubuntu 24.04 用户安装 MoeQuick Gate 后，可以：

- 创建代理配置
- 修改代理配置
- 删除代理配置
- 选择当前代理
- 开启 APT 代理
- 关闭 APT 代理
- 开启 NPM 代理
- 关闭 NPM 代理

即可。


---

# 12. Codex 开发约束

开发过程中：

- 不主动扩大需求
- 不提前实现未来功能
- 不引入未规划框架
- 不提前支持其他平台
- 不实现插件系统


每完成一个阶段：

需要汇报：

- 完成内容
- 修改文件
- 当前状态

等待下一阶段指令。


保持：

- 清晰架构
- 合理注释
- 可维护代码
